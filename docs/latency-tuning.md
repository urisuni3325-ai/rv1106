# 지연 시간 줄이기

같은 공유기에서 보통 **200~400ms** 정도가 나옵니다. 더 줄이고 싶을 때 손댈 곳을
영향이 큰 순서로 정리했습니다.

## 1. GOP(키프레임 간격) — 영향 가장 큼

```sh
./stream-tune.sh --gop 25    # 25fps 라면 1초에 한 번 키프레임
```

디코더는 키프레임이 와야 화면을 그리기 시작합니다. GOP 가 50~100 이면 앱을 켜고
2~4초 동안 검은 화면이 보이고, 패킷이 한 번 유실되면 그만큼 다시 기다립니다.
**GOP = 프레임레이트** 가 실시간 감시용으로 가장 무난합니다.

대역폭이 아깝다면 GOP 를 늘리는 대신 비트레이트를 줄이는 쪽이 체감이 좋습니다.

## 2. 비트레이트 — WiFi 상태에 맞추기

전파가 약한 곳에 보드를 두면 높은 비트레이트가 오히려 지연과 끊김을 만듭니다.

| 상황 | 권장 |
|---|---|
| 공유기와 가깝고 5GHz | 1080p / 25fps / 4~6Mbps |
| 일반적인 실내 2.4GHz | 1080p / 25fps / 2~3Mbps |
| 벽 너머, 전파 약함 | 720p / 25fps / 1~1.5Mbps |

```sh
./stream-tune.sh --width 1280 --height 720 --fps 25 --bitrate 1536 --gop 25
```

보드에서 신호 세기를 확인하려면 `./check-stream.sh` 의 "신호 세기" 항목을 보세요.
`-70dBm` 보다 나쁘면 위치를 옮기는 게 설정을 만지는 것보다 효과가 큽니다.

## 3. 해상도

SC3336 은 3MP(2304x1296)입니다. 폰 화면에서는 1080p 와 차이를 느끼기 어렵고,
인코딩·전송·디코딩 모든 단계의 지연이 늘어납니다. 실시간으로 볼 때는 1080p 이하를
권합니다. 나중에 확대해서 봐야 하는 용도라면 `--preset quality` 로 올리세요.

## 4. 앱이 이미 하고 있는 것

따로 설정할 필요는 없지만, 알아두면 증상 판단에 도움이 됩니다.

- **RTSP over TCP** — UDP 를 쓰지 않습니다. WiFi 에서 UDP 는 유실이 잦고, 유실은
  곧 키프레임까지의 대기로 이어집니다.
- **즉시 렌더** — 디코딩된 프레임을 타임스탬프에 맞춰 기다리지 않고 바로 그립니다.
  버퍼링 지연이 쌓이지 않습니다.
- **밀리면 버리기** — 디코더 입력 큐가 8프레임을 넘으면 다음 키프레임까지 버립니다.
  네트워크가 잠깐 막혔을 때 지연이 누적되지 않고 바로 현재 시점을 따라갑니다.
- **저지연 디코더 힌트** — 안드로이드 11 이상에서 `KEY_LOW_LATENCY` 를 켭니다.

## 5. 확인 방법

지연을 재려면 폰 화면에 스톱워치를 띄우고 그것을 카메라로 비춘 뒤, 실제 스톱워치와
앱 화면을 함께 사진으로 찍어 두 숫자 차이를 보면 됩니다.

문제가 앱인지 보드인지 가르려면 PC 에서 아래를 돌려 비교하세요. 비슷하다면 보드나
네트워크 쪽, PC 만 빠르면 앱 쪽입니다.

```sh
ffplay -fflags nobuffer -flags low_delay -rtsp_transport tcp rtsp://<보드IP>:554/live/0
```
