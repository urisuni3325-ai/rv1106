# af — RV1106 오토포커스

두피 스코프용 콘트라스트 검출 오토포커스. VCM(보이스코일)으로 렌즈를 움직이면서
화면 중앙의 선명도를 재고, 가장 선명한 위치에 멈춘다.

RV1106의 `rkaiq`에는 AF 모듈이 없다. 있어도 감시카메라용이라 "1m~무한대"를 탐색하도록
만들어져 있어서, 두피 스코프가 필요한 "12mm 근처 ±0.3mm"에는 맞지 않는다.
그래서 직접 구현한다. 접사에서는 탐색 범위를 좁게 박을 수 있는 쪽이 더 빠르고 안정적이다.

## 왜 GPIO 비트뱅 I2C인가

이 보드에서 하드웨어 I2C 컨트롤러는 두 개가 살아 있는데, 둘 다 이미 쓰이거나
핀헤더로 나와 있지 않다.

| 버스 | 붙어 있는 것 | 핀헤더 |
|---|---|---|
| i2c-3 | 0x14 (Goodix 터치) | ✗ 안 나옴 |
| i2c-4 | 0x30 (SC3336 카메라) | ✗ 카메라 FPC |

핀을 옮기려면 디바이스트리를 고치고 커널을 다시 빌드해야 한다. 그럴 필요가 없다 —
**I2C는 최소 클럭 속도 규정이 없어서** 유저스페이스에서 GPIO를 토글해도 규격에 맞는
통신이 된다. DW9714는 한 번에 3바이트만 쓰고, AF 한 번에 30여 회 쓰는 게 전부라
속도가 전혀 문제되지 않는다.

```
AF 탐색 1회 = 약 33회 전송 = 비트뱅 10kHz 기준 I2C에 33ms
```

나중에 제품화할 때는 SC3336(0x30)과 DW9714(0x0C)가 주소가 다르므로
i2c-4를 그대로 공유하면 된다. `gpio_i2c` 함수만 바꿔 끼우면 나머지는 그대로 쓴다.

## 배선

```
VCM 모듈            RV1106
  SDA      ───────  GPIO1_A0  (sysfs 번호 32)
  SCL      ───────  GPIO1_A1  (sysfs 번호 33)
  AF-VCC   ───────  3.3V      ※ 아래 "A안/B안" 확인 후
  AF-GND   ───────  GND

  SDA ── 4.7kΩ ── 3.3V        풀업 필수 (I2C는 오픈 드레인)
  SCL ── 4.7kΩ ── 3.3V
```

Rockchip GPIO 번호 = `뱅크 × 32 + 그룹 × 8 + 인덱스` (그룹 A=0, B=1, C=2, D=3).
`GPIO1_A0` → `1×32 + 0×8 + 0 = 32`.

### A안 / B안 — 모듈에 드라이버 IC가 있는가

`AF-VCC`에 전압을 넣기 전에 반드시 확인한다.

| AF-VCC↔AF-GND 저항 | 정체 | AF-VCC에 넣을 것 |
|---|---|---|
| 수 kΩ 이상 / OPEN | **A안** — 모듈에 DW9714 탑재 | 3.3V |
| 10~30Ω | **B안** — VCM 코일 직결 | **고정 전압 금지.** 전류 제한 필요 |

B안에 3.3V를 직결하면 정격의 2~3배 전류가 흘러 코일이 손상된다.
B안이면 DW9714 칩을 따로 달고, 그 IC에 3.3V를 넣는다.

## 빌드

> 처음 해 보신다면 **[docs/af-guide.md](../../docs/af-guide.md)** 를 보세요.
> WSL2 설치부터 배선, 실행까지 단계별로 적어 뒀습니다.

### 보드용 — SDK 없이 (권장)

Luckfox SDK(10GB+)는 필요 없다. 우분투 기본 크로스컴파일러로 **정적 링크**하면
보드 rootfs의 libc 종류와 무관하게 실행된다. 리눅스가 필요하며 **WSL2로 충분하다.**

```bash
sudo apt install gcc-arm-linux-gnueabihf
make board
adb push af_tool /root/
adb shell chmod +x /root/af_tool
```

약 500KB 정적 바이너리가 나온다.

### 보드용 — SDK 툴체인이 있는 경우

```bash
export PATH=$PATH:<SDK>/tools/linux/toolchain/arm-rockchip830-linux-uclibcgnueabihf/bin
make CROSS_COMPILE=arm-rockchip830-linux-uclibcgnueabihf-
```

### 테스트 (보드 없이)

탐색 로직과 선명도 계산은 하드웨어와 분리돼 있어서 부품 없이 검증된다.

```bash
make test
```

합성 초점 곡선으로 봉우리 탐색·격자 밖 보간·평평한 장면 감지·측정 실패 처리를
확인하고, 선명도 쪽은 균일/체커 이미지와 ROI 잘림을 확인한다.

## 사용 순서

### 1. 배선 확인 — 컴파일 없이 셸에서

`af_tool`을 올리기 전에 핀이 실제로 움직이는지부터 본다.

```bash
echo 32 > /sys/class/gpio/export
echo 33 > /sys/class/gpio/export
echo low  > /sys/class/gpio/gpio32/direction   # SDA를 0V로
echo in   > /sys/class/gpio/gpio32/direction   # 풀업이 3.3V로 올림
cat /sys/class/gpio/gpio32/value               # 1 이 나와야 정상
```

`in` 상태에서 값이 `0`이면 풀업이 없거나 어딘가 단락된 것이다.

### 2. I2C 스캔

```bash
./af_tool scan
```

| 결과 | 의미 |
|---|---|
| `0x0C 응답` | **A안 확정.** DW9714 정상 |
| `0x3C 응답` | OV5640 센서 — I2C 배선이 살아 있다는 증거 |
| 아무것도 없음 | 풀업 / GND 공통 / 전원 / SDA·SCL 뒤바뀜 확인 |

### 3. 렌즈가 실제로 움직이는지

```bash
./af_tool sweep --step 128
```

렌즈를 옆에서 보면 미세하게 앞뒤로 움직인다. 안 움직이면 여기서 멈추고
전원과 저항값(A안/B안)을 다시 본다.

### 4. 카메라 노드 찾기

```bash
./af_tool list-video
```

`/dev/video0`~`video20` 중 캡처 가능한 것만 나온다.

⚠️ **rkipc가 카메라를 점유하고 있으면 열리지 않는다.** 그때는 잠시 멈춘다.

```bash
killall rkipc          # 또는  /etc/init.d/S*rkipc stop
```

### 5. 선명도 확인

```bash
./af_tool score --video /dev/video0
```

렌즈를 손으로 돌려 초점을 맞췄다 흐렸다 하면서 `정규화` 값이 오르내리는지 본다.
값이 반응하지 않으면 ROI가 엉뚱한 곳이거나 피사체에 무늬가 없는 것이다.
**신문지나 자를 찍으면 확실하다.**

### 6. 오토포커스

```bash
./af_tool af --video /dev/video0 -v --save
```

`-v`는 모든 측정값을 출력한다. 초점 곡선이 실제로 봉우리 모양인지 확인할 수 있다.
`--save`는 찾은 위치를 `/userdata/af_focus.conf`에 저장한다.

### 7. 저장된 초점으로 즉시 복귀

```bash
./af_tool restore
```

**콘(거리 고정 경통)을 쓰면 이게 실사용의 기본 동작이 된다.** 거리가 기계적으로
고정돼 있으니 초점 위치도 항상 같다. 부팅 때 한 번 `restore`하면 AF를 돌릴 일이 거의 없고,
필요할 때만 보정용으로 `af`를 돌린다.

## 탐색 구간 좁히기

기본값은 전 구간(0~1023)을 훑는다. 실제 사용 위치를 알아낸 뒤에는 좁히는 게 좋다.

```bash
./af_tool af --from 520 --to 680 --step 16 --video /dev/video0
```

측정 횟수가 줄어 AF가 빨라지고, 머리카락 끝처럼 엉뚱한 곳에 초점이 물릴 확률도 낮아진다.
(단위 테스트에 이 효과를 확인하는 항목이 있다.)

## 설계 메모

- **히스테리시스** — VCM은 스프링 구조라 같은 DAC 값이라도 어느 방향에서 왔느냐에 따라
  실제 렌즈 위치가 달라진다. 탐색 중에는 항상 아래쪽에서 접근한다(`--backlash`, 기본 40).
- **밝기 정규화** — Tenengrad는 밝기에 비례해 커지므로, 자동 노출이 도는 중에는
  선명도 변화와 구분이 안 된다. 평균 휘도 제곱으로 나눠 보정한다.
- **포물선 보간** — 봉우리 좌우 세 점으로 정점을 추정해 탐색 스텝보다 미세한 위치를 낸다.
- **중앙 ROI** — 기본 25%. 전체를 보면 시야 가장자리의 머리카락에 초점이 물린다.

## 파일

| | |
|---|---|
| `gpio_i2c.c` | GPIO 비트뱅 I2C 마스터 (sysfs / chardev 백엔드) |

| `focus_score.c` | Tenengrad 선명도, NV12 휘도 평면 |

| `af_tool.c` | CLI |
| `test_af.c` | 호스트 단위 테스트 |

## 알려진 제약

- **실제 하드웨어에서 아직 검증되지 않았다.** VCM 모듈 입수 전에 작성했다.
  탐색 로직과 선명도 계산은 단위 테스트로 검증했지만, I2C 타이밍과 V4L2 캡처는
  보드에서 확인이 필요하다.
- `chardev` 백엔드는 커널의 오픈 드레인 지원에 의존한다. 실패하면 `--backend sysfs`(기본)를 쓴다.
- 캡처는 첫 평면이 8비트 휘도인 포맷(NV12/NV21/NV16/GREY)만 지원한다.
