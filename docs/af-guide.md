# 오토포커스 붙이기 — 단계별 안내

VCM(렌즈를 앞뒤로 움직이는 코일)을 달아서 자동 초점을 만드는 과정입니다.
처음부터 끝까지 순서대로 따라 하시면 됩니다.

## 명령을 어디서 실행하나

이 문서에는 **세 군데**에서 실행하는 명령이 섞여 있습니다. 매번 표시해 뒀습니다.

| 표시 | 어디 | 어떻게 여나 |
|---|---|---|
| 🖥️ **PC · cmd** | 윈도우 명령 프롬프트 | 시작 → `cmd` 입력 |
| 🐧 **PC · Ubuntu** | WSL2 우분투 창 | 시작 → `Ubuntu` 입력 (3단계에서 설치) |
| 📟 **보드** | 보드 안의 리눅스 | 🖥️ 에서 `adb shell` 입력 |

📟 에서 빠져나오려면 `exit` 를 칩니다.

## 준비물

| | 개수 | 비고 |
|---|---|---|
| VCM 카메라 모듈 (OV5640 AF 등) | 1 | VCM만 씁니다 |
| 4.7kΩ 저항 | 2 | I2C 풀업용. 필수입니다 |
| 점퍼선 (암-암) | 4~8 | |
| 멀티미터 | 1 | 1단계에 꼭 필요합니다 |
| 브레드보드 | 1 | 있으면 편합니다 |

---

# 1단계 — 전원 넣기 전에 저항부터 잰다

**이 단계를 건너뛰면 VCM이 탈 수 있습니다.**

모듈의 **23번(AF-VCC)** 과 **24번(AF-GND)** 사이 저항을 멀티미터로 잽니다.

| 측정값 | 의미 | 다음 |
|---|---|---|
| **수 kΩ 이상 또는 OPEN** | **A안** — 모듈에 DW9714 드라이버 IC가 있음 | 그대로 진행 |
| **10~30Ω** | **B안** — VCM 코일이 직접 나와 있음 | 아래 경고 참조 |

> ⚠️ **B안이면 AF-VCC에 3.3V를 직접 연결하면 안 됩니다.**
> 코일이 15Ω이면 3.3V에서 220mA가 흘러 정격의 2~3배가 됩니다.
> B안일 때는 DW9714 칩을 따로 사서 중간에 넣고, 3.3V는 그 칩에 넣습니다.
> 급하게 확인만 하려면 3.3V와 코일 사이에 **100Ω 저항**을 직렬로 넣으세요(약 29mA, 안전).

아래 2단계부터는 **A안 기준**으로 씁니다.

# 2단계 — 배선

```
   VCM 모듈                          RV1106 보드
   ─────────                        ─────────────
   3번  SIO_D (SDA) ─────┬───────── GPIO1_A0
   5번  SIO_C (SCL) ────┬┼───────── GPIO1_A1
   23번 AF-VCC     ──────┼┼───────── 3.3V
   24번 AF-GND     ──────┼┼───────── GND
                         ││
                    4.7kΩ││4.7kΩ
                         ││
                        3.3V
```

**풀업 저항 2개를 빠뜨리지 마세요.** I2C는 오픈 드레인 방식이라, 저항이 없으면
신호가 HIGH로 올라가지 못해 아무것도 동작하지 않습니다.

GND는 반드시 보드와 모듈이 **공통**이어야 합니다.

> 💡 처음 한 번은 센서 전원(AVDD 2.8V / DOVDD 2.8V / DVDD 1.5V)까지 다 넣는 걸
> 권합니다. 그러면 9단계 스캔에서 센서(0x3C)도 같이 보여서 **배선이 맞다는 증거**가
> 됩니다. 확인이 끝나면 VCM 관련 선만 남겨도 됩니다.

# 3단계 — PC에 Ubuntu 설치 (WSL2)

보드용 프로그램을 만들려면 리눅스가 필요합니다. 윈도우 안에 우분투를 넣는 게
WSL2이고, 윈도우를 지우거나 하지 않습니다.

🖥️ **PC · cmd** — **관리자 권한으로** 실행하세요 (시작 → `cmd` 우클릭 → 관리자 권한으로 실행)

```cmd
wsl --install -d Ubuntu
```

설치가 끝나면 **PC를 재부팅**합니다. 재부팅 후 우분투 창이 저절로 뜨면서
사용자 이름과 비밀번호를 물어봅니다. 아무거나 정하시고 **비밀번호는 기억해 두세요**
(나중에 `sudo` 쓸 때 필요합니다. 입력해도 화면에 아무것도 안 보이는 게 정상입니다).

이후에는 **시작 메뉴에서 `Ubuntu`** 를 검색해 열면 됩니다.

---

# 4단계 — 컴파일러 설치

🐧 **PC · Ubuntu**

```bash
sudo apt update
sudo apt install -y build-essential gcc-arm-linux-gnueabihf
```

몇 분 걸립니다. 확인:

```bash
arm-linux-gnueabihf-gcc --version
```

버전 번호가 나오면 성공입니다.

> Luckfox SDK는 **필요 없습니다.** 정적 링크로 만들어서 보드의 라이브러리에
> 의존하지 않게 했기 때문입니다.

# 5단계 — 소스 최신화

🐧 **PC · Ubuntu** — 윈도우의 `C:\Users\user\rv1106` 폴더는 우분투에서
`/mnt/c/Users/user/rv1106` 으로 보입니다.

```bash
cd /mnt/c/Users/user/rv1106
git pull
```

`user` 부분은 실제 윈도우 사용자 이름으로 바꾸세요. 폴더 위치가 기억나지 않으면
🖥️ **PC · cmd** 에서 `echo %USERPROFILE%` 로 확인할 수 있습니다.

`git pull` 이 `fatal: not a git repository` 라고 하면 클론이 아니라 ZIP을 푼
폴더입니다. 그때는 새로 받으세요.

```bash
cd /mnt/c/Users/user
git clone https://github.com/urisuni3325-ai/rv1106.git
cd rv1106
git checkout claude/rv1106-sc3336-wifi-streaming-p74k9v
```

# 6단계 — 빌드

🐧 **PC · Ubuntu**

먼저 보드 없이 돌아가는 검사부터 해 봅니다.

```bash
make -C device/af test
```

```
23 개 검사 중 0 개 실패
```

이렇게 나와야 합니다. 이건 탐색 알고리즘과 선명도 계산이 제대로 동작하는지
보는 것이고, 부품이 없어도 돌아갑니다.

이제 보드용으로 만듭니다.

```bash
make -C device/af board
```

마지막에 이렇게 나오면 성공입니다.

```
빌드 완료. 보드로 복사하세요:
  adb push af_tool /root/  &&  adb shell chmod +x /root/af_tool
```

`device/af/af_tool` 파일이 생겼습니다 (약 500KB).

# 7단계 — 보드에 복사

보드를 USB로 PC에 연결한 상태에서,

🖥️ **PC · cmd**

```cmd
cd %USERPROFILE%\rv1106
adb devices
```

보드가 목록에 나와야 합니다. `adb` 가 없다는 오류가 나면
[docs/getting-started.md](getting-started.md) 의 adb 설치 부분을 먼저 보세요.

```cmd
adb push device\af\af_tool /root/
adb shell chmod +x /root/af_tool
```

# 8단계 — 배선 확인 (프로그램 없이)

프로그램을 돌리기 전에 핀이 실제로 살아 있는지부터 봅니다.

🖥️ **PC · cmd**

```cmd
adb shell
```

📟 **보드**

```sh
echo 32 > /sys/class/gpio/export
echo 33 > /sys/class/gpio/export

echo low > /sys/class/gpio/gpio32/direction
cat /sys/class/gpio/gpio32/value

echo in > /sys/class/gpio/gpio32/direction
cat /sys/class/gpio/gpio32/value
```

기대하는 결과:

| 명령 | 나와야 할 값 | 의미 |
|---|---|---|
| `low` 로 놓고 읽기 | `0` | 보드가 0V로 끌어내림 |
| `in` 으로 놓고 읽기 | **`1`** | **풀업 저항이 3.3V로 올림** |

**두 번째가 `0`이면 풀업 저항이 없거나 잘못 연결된 것입니다.** 여기서 멈추고
저항부터 확인하세요. 이걸 통과 못 하면 다음 단계는 전부 실패합니다.

33번도 같은 방법으로 확인합니다.

숫자 32와 33은 어디서 나왔냐면 — Rockchip은 `뱅크×32 + 그룹×8 + 인덱스` 로
번호를 매깁니다. `GPIO1_A0` = 1×32 + 0×8 + 0 = **32**, `GPIO1_A1` = **33** 입니다.

# 9단계 — I2C 스캔

📟 **보드**

```sh
/root/af_tool scan
```

| 결과 | 의미 | 다음 |
|---|---|---|
| `0x0C 응답` | **DW9714 정상.** A안 확정 | 10단계로 |
| `0x3C 응답` | OV5640 센서 — 배선이 살아 있다는 증거 | 좋은 신호 |
| `응답 없음` | 아래 문제 해결 참조 | |

# 10단계 — 렌즈가 실제로 움직이는지

📟 **보드**

```sh
/root/af_tool sweep --step 128
```

렌즈를 **옆에서 비스듬히 보면** 아주 미세하게(0.3mm 정도) 앞뒤로 움직입니다.
밝은 곳에서 반사를 보면 알기 쉽습니다.

**안 움직이면 여기서 멈추세요.** 전원(AF-VCC)이 들어갔는지, 1단계 저항 측정이
A안이 맞았는지 다시 봅니다. 이 단계를 통과 못 하면 오토포커스는 당연히 안 됩니다.

---

# 11단계 — 카메라 노드 찾기

보드에는 `/dev/video0` 부터 `video20` 까지 21개가 있는데, 실제로 영상이 나오는 건
그중 일부입니다.

📟 **보드**

```sh
/root/af_tool list-video
```

나온 목록에서 `rkisp` 나 `mainpath` 같은 이름이 붙은 것을 씁니다.
아래에서는 `/dev/video0` 이라고 가정하고 씁니다 — **실제로 나온 번호로 바꿔서** 쓰세요.

> ⚠️ **rkipc가 카메라를 쓰고 있으면 열리지 않습니다.** 다음 단계에서
> "다른 프로그램이 카메라를 쓰고 있으면" 이라는 오류가 나오면 잠시 멈추세요.
> ```sh
> killall rkipc
> ```
> 확인이 끝나고 스트리밍을 다시 켜려면 보드를 재부팅하거나 `RkLunch.sh &` 를 씁니다.

---

# 12단계 — 선명도가 반응하는지

**두피 말고 신문지나 자를 찍으세요.** 무늬가 뚜렷해야 초점 차이가 잘 보입니다.

📟 **보드**

```sh
/root/af_tool score --video /dev/video0
```

```
프레임 2304x1296 (stride 2304), ROI 576x324 @ (864,486)
  Tenengrad  1234.56
  평균 밝기  98.3
  정규화     0.1278
```

이제 **렌즈를 손으로 살짝 돌려 초점을 흐렸다 맞췄다** 하면서 여러 번 실행해 보세요.

- 초점이 맞을수록 **정규화 값이 커져야** 합니다
- 값이 전혀 안 변하면 → 피사체에 무늬가 없거나, ROI(화면 가운데 25%)에
  아무것도 안 들어와 있는 것입니다

# 13단계 — 오토포커스

📟 **보드**

```sh
/root/af_tool af --video /dev/video0 -v --save
```

`-v` 를 붙이면 측정값이 전부 나옵니다. **이 숫자들이 봉우리 모양을 그리는지**
보는 게 중요합니다.

```
  위치    0  선명도       0.02  밝기   95.1
  위치   64  선명도       0.05  밝기   95.3
  ...
  위치  576  선명도       0.31  밝기   96.0
  위치  640  선명도       0.28  밝기   96.1
  ...

결과: 성공
  최적 위치  592
  선명도     0.3140 (최저 0.0180, 비 17.44배)
  측정 횟수  33
```

| 결과 메시지 | 의미 | 대처 |
|---|---|---|
| `성공` | 정상 | — |
| `봉우리 없음` | 무늬가 없거나 렌즈가 안 움직임 | 10·12단계 다시 |
| `봉우리가 구간 끝` | 초점 범위 밖 | 렌즈를 돌려 대략 맞춘 뒤 다시 |
| `측정 실패` | I2C 또는 카메라 오류 | 9·11단계 다시 |

`--save` 는 찾은 위치를 `/userdata/af_focus.conf` 에 저장합니다.

---

# 14단계 — 저장된 초점으로 복귀

📟 **보드**

```sh
/root/af_tool restore
```

**콘(거리 고정 경통)을 만들고 나면 이게 평소 동작이 됩니다.** 거리가 기계적으로
고정되니 초점 위치도 항상 같아서, 부팅할 때 한 번 복귀시키면 끝입니다.
AF는 가끔 보정할 때만 돌립니다.

부팅 시 자동 실행은 `/etc/init.d/` 에 스크립트를 하나 넣으면 됩니다 —
이건 위 단계가 다 확인된 뒤에 하시죠.

# 탐색 범위 좁히기 (선택)

13단계에서 최적 위치가 대략 어디인지 알았다면, 그 주변만 찾도록 바꿀 수 있습니다.

```sh
/root/af_tool af --from 520 --to 680 --step 16 --video /dev/video0
```

측정 횟수가 줄어 **AF가 빨라지고**, 머리카락 끝 같은 엉뚱한 곳에 초점이 물릴
확률도 낮아집니다.

# 문제 해결

| 증상 | 원인 | 해결 |
|---|---|---|
| `scan` 에 아무것도 안 나옴 | 풀업 저항 없음 | 4.7kΩ 2개를 3.3V에 |
| | GND 공통 아님 | 보드와 모듈 GND 연결 |
| | SDA/SCL 바뀜 | 32↔33 서로 바꿔 연결 |
| | 모듈 전원 없음 | AF-VCC 확인 |
| `GPIO 32 export 실패` | 다른 드라이버가 핀을 점유 | 다른 GPIO로 옮기고 `--sda`/`--scl` 로 지정 |
| `SCL 이 HIGH 로 안 올라옴` | 풀업 문제 | 8단계로 돌아가기 |
| 카메라 열기 실패 | rkipc가 점유 | `killall rkipc` |
| `지원하지 않는 픽셀 포맷` | 캡처 노드를 잘못 고름 | `list-video` 로 다른 번호 시도 |
| 렌즈가 안 움직임 | B안인데 3.3V 직결 | 1단계 저항 재측정 |
| `봉우리 없음` | 피사체에 무늬가 없음 | 신문지·자를 찍기 |

## 지금 확인된 것 / 안 된 것

- ✅ 탐색 알고리즘·선명도 계산 — 단위 테스트 23개 통과
- ✅ 보드용 정적 바이너리 빌드 (ARM 32비트)
- ⚠️ **실제 VCM에서는 아직 검증 안 됨** — I2C 타이밍과 V4L2 캡처는
  부품이 와야 확인됩니다. 위 단계에서 막히는 곳이 있으면 알려주세요.
