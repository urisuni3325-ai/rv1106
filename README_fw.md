# Homion 이온수기 / 필터 칩 쓰기 치구 펌웨어

소스는 두 빌드가 **완전히 동일**하고 `user_define.h` 의 `FILTER_WRITER` 한 줄만 다르다.
헷갈리지 않게 폴더를 나눠 두었다.

| 폴더 | FILTER_WRITER | 용도 |
|---|---|---|
| `fw_ionizer/` | `0` | 이온수기 본체 프로그램 |
| `fw_jig/` | `1` | 필터 칩 쓰기 치구 프로그램 |

각 폴더의 4개 파일을 프로젝트에 그대로 넣는다.

```
aes128.c   main.c   Display_16D33.c   user_define.h
```

`GD25d10.c` · `Ntc.c` · `COMSEG_LCD.h` 등 나머지 파일은 변경이 없다.
인코딩은 원본 그대로 (`Display_16D33.c` 만 UTF-8, 나머지는 CP949), 줄바꿈은 CRLF.

---

## 1. 이온수기 본체 (`fw_ionizer`)

### 필터 칩 인증

| 단계 | 내용 | 실패 시 |
|---|---|---|
| 칩 존재 | JEDEC ID `0x9F` 가 `FF`/`00` 이거나 제조사가 `GD25_MID_EXPECT` 가 아니면 미연결 | E01 / E02 |
| 키 유도 | `AES(master_key, UID)` — 칩 고유 UID(`0x4B`) 기반 | — |
| 복호화 | MAGIC 불일치 → 위조 | E03 / E04 |
| chip_id | 암호문 안의 chip_id 가 `UID[0..3]` 와 다르면 복제 | E03 / E04 |
| CRC / 범위 | 손상 · 범위 초과 | E01 / E02 |
| **되쓰기** | 같은 칩의 잔량이 기록보다 `RB_MARGIN_L`(20L) 이상 늘면 롤백 | **E03 / E04** |

`LoadFilter()` 가 실패 원인을 `last_load_err1/2` 에 남기고,
`F1/F2_life_reload()` 와 `Filter_life_check()` 가 원인별로 에러를 나눈다.

### 되쓰기 차단 기록 (데이터 플래시)

`START_ADDR 0x0E000000` 의 `FlashWrite()` 가 256바이트 페이지를 통째로 쓴다.

| 번지 | 용도 |
|---|---|
| 0 ~ 31 | 설정값 |
| 32 ~ 35 | `ADD_INIT` — `DATA_INIT` 매직 4바이트 (33·34·35 도 점유) |
| **36 ~ 87** | **되쓰기 차단 기록** |
| 88 ~ 255 | 여유 |

슬롯별로 최근 `RB_HIST`(4) 개 칩의 `chip_id` 와 최소 잔량(L) 을 남긴다.
잔량이 `RB_STEP_L`(10L) 줄어들 때마다 갱신해 플래시 수명을 아낀다.

- `Rb_Load()` — `Set_eep_init()` 맨 앞 (그 함수가 초기화 분기에서 FlashWrite 를 하므로 반드시 앞)
- `Rb_Sync_Buffer()` — `FlashWrite()` 안 (Buffer 는 부팅 시 0 이고 플래시에서 되읽지 않는다)
- `Rb_Check()` — 판정. `FILTER_WRITER 1` 에서는 아무 것도 하지 않는다

기록이 비어 있으면(최초 적용 · 기판 교체) 현재 상태를 기준으로 등록하므로,
기판을 갈고 기존 필터를 계속 쓰는 서비스 작업은 막히지 않는다.

**한계** — 칩을 4개 넘게 돌려 끼우면 등록 칸이 밀려 우회할 수 있다. `RB_HIST` 를 키우면
칩당 6바이트씩 더 쓴다 (88번지 이후 여유 있음).

## 2. 쓰기 치구 (`fw_jig`)

본체 MCU · 본체 화면 · 본체 버튼을 그대로 쓴다. 별도 장비가 아니라 펌웨어만 바꿔 넣는다.

### 버튼

| 버튼 | 동작 |
|---|---|
| 온수 | 3000 L 선택 |
| 정수 | 101 L |
| 냉수 | 71 L |
| 알칼리수 | 31 L |
| 냉알칼리수 | 6 L |
| **세정 (짧게)** | 굽기 모드 순환 — 빨강 정품 / 파랑 키위조 / 노랑 ID위조 |
| **세정 (3초)** | 되쓰기 차단 기록 전체 초기화 → `- 0 -  - 0 -` + 띠링 |
| **용량** | UID 확인 화면 토글 |
| **출수** | 굽기 (성공 시 해당 슬롯 기록 자동 초기화) |

### 화면

| 상태 | 좌(필터1) | 우(필터2) | 출수버튼 |
|---|---|---|---|
| 대기 | 선택값 | 선택값 | 모드색 (빨강/파랑/노랑) |
| 쓰는중 | `- - -` | `- - -` | 소등 |
| 완료 | 읽은 값 | 읽은 값 | 초록 + 띠링 |
| 실패 | `E`+코드 | `E`+코드 | 빨강 점멸 |

세정 LED 가 켜져 있으면 위조 모드로 구운 것이다 (완료 상태에서도 확인 가능).

### E 코드

| 표시 | 원인 |
|---|---|
| `E12` | 칩 미연결 / 하네스 불량 / 제조사 불일치 |
| `E11` | 기록 후에도 전부 `0xFF` — 쓰기 실패 (WP 핀·전원 확인) |
| `E01` | 키 불일치 |
| `E03` | CRC 손상 |
| `E04` | 값이 3000L 초과 |
| `E05` | chip_id 불일치 |
| `E09` | 읽은 값 ≠ 쓴 값 |

### UID 확인 화면 (용량 버튼)

좌 = 필터1 UID 16바이트 합 % 1000, 우 = 필터2. 100ms 마다 다시 읽는다.

| 표시 | 뜻 |
|---|---|
| `080  080` | UID 가 전부 `0xFF` → `0x4B` 미지원 (16×255=4080) |
| `000  000` | UID 가 전부 `0x00` → 반단선 / 미연결 |
| 칩 바꿔도 같은 값 | UID 가 칩별로 다르지 않음 → 복사 방지 무효 |
| 칩마다 다른 값 | 정상 |

### 위조 칩 굽기 (세정 짧게)

| 모드 | 굽는 방식 | 본체에서 |
|---|---|---|
| 정품 (빨강) | 정상 키 + 정상 chip_id | 에러 없음 |
| 키위조 (파랑) | 다른 마스터 키 | `-1` → E03 / E04 |
| ID위조 (노랑) | 정상 키 + 틀린 chip_id | `-5` → E03 / E04 |

치구는 자기가 쓴 키로 되읽으므로 위조 칩도 **완료(초록)** 로 뜬다.
위조 여부는 본체 펌웨어로 읽었을 때 드러난다.

## 3. 양산 전 확인

1. **MCU 코드 보호(읽기 방지) 비트** — 마스터 키가 펌웨어 안에 평문 상수로 있다.
   이게 꺼져 있으면 나머지 보호가 전부 무의미하다.
2. **`GD25_MID_EXPECT`** — 치구 UID 화면이 정상이면 `0x4B` 는 동작한다.
   제조사 ID 는 `bJedecMid1/2` 로 확인한다. `0xC8` 이 아니면 매 부팅마다 E01/E02 가
   뜨므로 바로 알 수 있고, 그때 `GD25_MID_CHECK` 를 `0` 으로 둔다.
3. **필드에 나간 기존 칩** — 구 프로그램으로만 쓴 칩은 암호문 chip_id 가 UID 와 달라
   새 본체 펌웨어에서 E03/E04 가 난다. 필터를 먼저 새 방식으로 전환하고 본체 펌웨어를
   나중에 올리는 순서가 안전하다 (새 방식 칩은 구 펌웨어에서도 동작한다).

## 4. 시험 항목

| 시험 | 펌웨어 | 기대 |
|---|---|---|
| 정품 칩 | 본체 | 에러 없음 |
| 칩 빼고 전원 | 본체 | E01 / E02 |
| 빈 칩 (소거만) | 본체 | E01 / E02 |
| 키위조 칩 (파랑) | 본체 | E03 / E04 |
| ID위조 칩 (노랑) | 본체 | E03 / E04 |
| 20~30L 출수 후 처음 덤프한 20바이트 되쓰기 | 본체 | **E03 / E04** |
| 칩 A 덤프를 칩 B 에 기록 | 본체 | E03 / E04 |

## 5. 온수 라인 · 시험 스위치 (`user_define.h`)

온수 입수에는 솔레노이드가 없다. **부압밸브(MO226)** 가 달려 있고
**마이크로 펌프(S370D5-LP)** 가 만든 부압으로만 열린다. 펌프가 물을 못 빨면
어떤 밸브 조합으로도 온수가 나오지 않는다. 펌프의 수명 조건은
**30초 동작 / 30초 정지의 간헐 운전**이다.

| 스위치 | 기본 | 내용 |
|---|---|---|
| `PUMP_DRY_TICK` | 100 | 펌프가 도는데 온수 유량이 10초간 0 이면 펌프를 잠그고 E00. 출수를 멈추면 해제 |
| `FLUSH_PUMP_ON_TICK` / `FLUSH_PUMP_OFF_TICK` | 300 / 100 | 플러싱 펌프 간헐 운전 30초 동작 / 10초 정지 |
| `FLUSH_STEP_TICK` | 1800 | 플러싱 한 단계 180초 넘으면 중단 + E00 |
| `PRIME_MODE` | 0 | 펌프 교체 후 초기 급수 서비스 모드 |
| `VALVE_TEST_MODE` | 0 | 밸브 · 펌프 수동 시험 |
| `HOT_TEST_MODE` | 0 | 온수 고정 PWM 시험 |
| `FLUSH_STEP_DISP` / `FLOW_DEBUG_DISP` | 0 | 플러싱 단계 · 유량 표시 |

**양산 펌웨어는 위 시험 스위치 네 개(`PRIME_MODE`, `VALVE_TEST_MODE`,
`HOT_TEST_MODE`, `FLUSH_STEP_DISP`, `FLOW_DEBUG_DISP`)를 전부 `0` 으로 둔다.**
보호 스위치(`PUMP_DRY_TICK` 이하 세 줄)는 양산에서도 그대로 둔다.

### 초기 급수 (`PRIME_MODE 1`)

| 버튼 | 기능 |
|---|---|
| 온수 | 시작 (대기 · 완료 · 실패 상태에서) |
| 용량 | 중단 |
| 알칼리 | 유량 누적 0 |

화면 좌 3자리 = `[단계][반복 2자리]`, 우 3자리 = 온수 유량센서(PE7) 누적 펄스.

| 단계 | 내용 |
|---|---|
| 0 | 대기 |
| 1 | 배기 급수 — 5SV · 7SV · 8SV 열고 펌프 5초 ON |
| 2 | 배기 급수 — 펌프 3초 OFF (간헐 운전). 최대 24회 |
| 3 | 출수 확인 — 5SV 만 열고(7SV · 8SV 닫음) 펌프. 30초 안에 PE7 300 펄스 |
| 8 | 실패 — 펌프 정지, 1SV 까지 잠금 |
| 9 | 완료 |

히터는 이 모드에서 항상 정지한다 (빈 히터 가열 금지).
